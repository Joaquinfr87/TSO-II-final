# Resumen de Arquitectura e Infraestructura: Red Bancaria

* **Materia:** Sistemas Operativos 2
* **Servidor Central:** `dc1.sudoers.lan` (Debian 12 — IP fija `192.168.0.2`)
* **Dominio Corporativo:** `SUDOERS.LAN`
* **Red LAN Principal:** `192.168.0.0/24`

---

## 1. Zonas de Red y Perímetro

* **Zona A (Perímetro / Gateway):** Router TP-Link TL-WR850N (`192.168.0.1`). Gestiona la salida WAN y NAT hacia Internet. Su servicio DHCP interno está desactivado para evitar conflictos en la red.
* **Zona C (Puestos Operativos / Cajas):** Subred reservada fija (`192.168.0.60`–`.99`). Terminales Linux Kiosk restringidas únicamente a la aplicación transaccional del banco, recursos SMB locales e impresión.
* **Zona D (Administración y Gerencia):** Segmento dinámico (`192.168.0.100`–`.199`) para personal administrativo en Windows y rango estático (`192.168.0.50`–`.52`) asignado exclusivamente al equipo de TI.

---

## 2. Servidor Host `dc1` (`192.168.0.2`)

La máquina física ejecuta una arquitectura dividida en tres capas de procesamiento:

### B.1: Servicios Nativos (Host Debian 12)
* **Samba 4 AD DC:** Controlador de Dominio principal. Administra la zona DNS autoritativa interna (`53`), la autenticación centralizada Kerberos/LDAP (`88`, `389`) y las carpetas compartidas SMB (`445`) con permisos por rol (`//dc1/cajas`, `//dc1/creditos`, `//dc1/gerencia`).
* **Chrony (NTP):** Puerto `123/udp`. Provee sincronización de tiempo estricta para tickets Kerberos y firmas de operaciones.
* **nftables & SSH endurecido:** Política de cortafuegos *DROP* por defecto; acceso al puerto `22/tcp` filtrado únicamente para las IPs de administración (`.50` a `.52`).
* **Restic / Borg Backup:** Copias de seguridad automáticas locales mediante tareas Cron sin exponer puertos de red.

### B.2: Capa Docker (`docker-compose`)
* **Nginx Reverse Proxy:** Punto único de entrada web HTTPS (`80`/`443` TLS). Inspecciona certificados y enruta las peticiones internas hacia el Core Bancario, Webmail, CUPS y Zabbix.
* **Kea DHCP (`network_mode: host`):** Escucha en broadcast (`67/udp`). Entrega configuraciones de red, asigna como DNS exclusivo al DC (`192.168.0.2`) y gestiona reservas por dirección MAC.
* **PostgreSQL:** Base de datos del Core Bancario. Confinada a la red interna de Docker (`5432/tcp`), sin exposición directa a la LAN.
* **App Core Bancario:** Aplicación web para la gestión de pagos, depósitos y retiros en cajas.
* **Postfix + Dovecot + Roundcube:** Correo electrónico institucional validado contra el LDAP de Samba.
* **CUPS & Portainer:** Servidor de impresión de comprobantes (`631/tcp`) y consola de supervisión de contenedores restringida a TI (`9443/tcp`).

### B.3: Virtualización KVM / libvirt
* **VM Zabbix Server (`192.168.122.4`):** Máquina virtual aislada tras una red NAT (`virbr0: 192.168.122.0/24`). No admite conexiones directas desde los puestos de la LAN; su interfaz web se publica de forma segura a través del proxy inverso Nginx. El monitoreo opera mediante **agentes activos** (`10051/tcp`) que envían métricas desde los clientes hacia la VM.

## [ZONA B] Host Servidor `dc1`
* **Especificaciones:** Debian 12 — IP fija `192.168.0.2` — FQDN: `dc1.sudoers.lan`

### [B.1] Servicios Nativos (Host Físico)
* 🟡 **Samba 4 AD DC:**
  * **DNS (`53/udp`, `53/tcp`):** Resuelve nombres internos para toda la LAN.
  * **Kerberos / LDAP (`88/tcp`, `389/tcp`):** Autenticación centralizada de usuarios y estaciones de trabajo.
  * **SMB File Shares (`445/tcp`):** Carpetas compartidas con permisos filtrados por grupos de AD (`//dc1/cajas`, `//dc1/creditos`, `//dc1/gerencia`).
* 🟡 **Chrony NTP (`123/udp`):** Sincronización horaria estricta para firmas digitales, tickets y transacciones.
* 🔴 **nftables (Firewall):** Política *DROP* por defecto. Solo las IPs `.50`–`.52` tienen acceso a los puertos de gestión.
* 🔴 **OpenSSH (`22/tcp` endurecido):** Restringido exclusivamente a las IPs de administración (`192.168.0.50` a `.52`).
* 🔴 **Restic Backup:** Tareas nativas vía cron para copias de seguridad locales seguras (sin puertos expuestos).

### [B.2] Capa Docker (`docker-compose`)
* 🟢 **Nginx Reverse Proxy (`80/tcp`, `443/tcp`):** Punto único de entrada web con inspección de certificados SSL/TLS:
  * `https://core.sudoers.lan` $\rightarrow$ 🟢 App Core Bancario (Cajas y Operaciones).
  * `https://mail.sudoers.lan` $\rightarrow$ 🟢 Webmail Roundcube (Oficiales y Gerencia).
  * `https://print.sudoers.lan` $\rightarrow$ 🟡 CUPS Impresión de contratos y comprobantes (`631` interno).
  * `https://zabbix.sudoers.lan` $\rightarrow$ 🔴 VM Zabbix (`192.168.122.4`) *(Acceso exclusivo para Admins TI)*.
* 🟡 **Kea DHCP (`network_mode: host`, `67/udp`):** Asignación de direccionamiento IP dinámico, reservas por MAC y parámetros DNS/Gateway.
* 🟡 **Postfix / Dovecot (`25/tcp`, `143/tcp`):** Servidor de correo institucional con autenticación contra el LDAP de Samba.
* 🔴 **PostgreSQL (`5432/tcp`):** Base de datos del Core Bancario, **aislada en red interna Docker** (sin exposición a la LAN).
* 🔴 **Portainer (`9443/tcp`):** Panel de gestión de contenedores Docker, accesible únicamente por Admins TI.

### [B.3] Virtualización KVM / libvirt
* **Red virtual aislada:** `virbr0` (NAT `192.168.122.0/24`)
* 🔴 **VM Zabbix Server (`192.168.122.4`):**
  * Inalcanzable de forma directa desde la red LAN (aislada por NAT).
  * Web UI publicada **únicamente** a través del proxy inverso Nginx para personal de TI.
  * Monitoreo mediante **Agente Activo (`10051/tcp`)**: las estaciones y el host empujan las métricas hacia el servidor.

## [ZONA C] Puestos Operativos / Ventanillas
* **Rango DHCP:** `192.168.0.60`–`.99` (Reservas fijas por MAC)
* **Estaciones:** Terminales de caja con Linux Debian Kiosk.
* **Alcance de acceso:**
  * 🟢 Web Core Bancario (`https://core.sudoers.lan`)
  * 🟡 Recurso compartido Samba (`//dc1/cajas`)
  * 🟡 Servidor de impresión CUPS (Comprobantes)
  * Telemetría mediante Zabbix Agent (Modo Activo)

## [ZONA D] Administración y Gerencia
* **Rango DHCP usuarios:** `192.168.0.100`–`.199` (Dinámico)
* **Rango fijo TI:** `192.168.0.50`–`.52` (Reservas estáticas)
* **Estaciones:** Windows 10/11 integradas al Dominio AD y equipos de administración.
* **Alcance de acceso según rol:**
  * **Oficiales / Gerencia:** Webmail Roundcube, recursos compartidos departamentales (`//dc1/creditos`, `//dc1/gerencia`), GPOs y scripts de inicio de sesión (`logon script`).
  * 🔴 **Admins TI (`.50`–`.52`):** Acceso SSH al host, consola web de Portainer y administración de Zabbix.
